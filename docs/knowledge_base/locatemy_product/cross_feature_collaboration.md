# 跨 Feature 协作规范

LocateMY 的跨 Feature 产品边界和组合语义；不规定技术选型或编码方式。AI 只参与设计与
审查，所有可提交代码和测试由两名学生亲自编写。

## 边界与权威

- Feature 是可独立设计、实现、验证的业务能力，不按页面、表或 ViewModel 划分。
- Feature 独占其业务、内部状态、数据和离线队列；消费者只用提供方的用途契约，不接触其内部模型。
- 已批准设计是契约唯一权威。实现者发现缺口、冲突、新依赖或例外时，提交设计问题并等待项目负责人批准，不自行改变跨 Feature 行为。

## 两类协作契约

- **同步能力**处理查询或用户动作，返回明确成功、失败或不可用。
- **领域事件**只陈述已发生事实；消费者可重复处理。即时用户反馈走同步工作流，不以订阅失败伪装成功。

## 应用壳与组合用例

- 应用壳拥有导航和跨 Feature 工作流，只依赖公开契约；它汇聚地点详情、A/B 比较、适配度和房产风险快照。
- 唯一直接结果依赖：Infrastructure 使用 Transportation 的公开交通连通性分计算 ICI，且复用同一结果。
- 组合结果保留各输入的可用性、来源、日期、口径与原因；必需输入缺失即不可用。风险快照的警区、安全分、附近隐患数缺一则保留旧值或失败。

## 共同地点与分析结果

- Map/Location 独占可变地点上下文（当前选点、A/B）；其他 Feature 只接收不可变地点引用或快照。站点选中不改变分析地点。
- 跨 Feature 分析结果必须带地点与范围、产生时间、来源日期、可用性/原因、口径或不可比原因；指标归其分析 Feature。

## 认证、离线与导航

- 会话变化由应用壳发布；私有 Feature 各自清理或恢复，且保持账户隔离。
- 离线创建 Feature 独占队列；以带账户与关联标识的结果公开同步状态。“已排队”不等于“已创建”。
- 应用壳拥有导航；Feature 输出业务导航意图。登录、退出、切换账户重置私有导航；公共地点是否恢复须显式定义。

## 地图贡献与验证

- Map/Location 拥有底图、选点、手势；其他数据 Feature 以声明式图层贡献提供显示条件、内容和点击意图。
- 每份 Feature 契约卡列出：职责/非职责、拥有状态、同步能力、事件、输入输出语境、依赖、认证/离线/错误、地图/导航贡献、缺口、验收场景。
- 提供方验证公开契约；应用壳验证账户切换、离线同步、分析不可用、A/B 不可比较、风险快照创建/刷新。
