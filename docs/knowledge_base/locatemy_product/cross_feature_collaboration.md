# 跨 Feature 协作规范

2026-09-17 用户确认整体精简。Feature 仍代表可独立观察的业务能力；协作以普通页面参数和具名业务服务表达，不要求每个小功能拥有完整多层目录。

## 业务边界

- 各 Feature 拥有其业务规则、数据读取和结果解释。公共分析不依赖账户范围开启／关闭协议。
- 地图拥有当前选点、地点 A/B；分析接收明确的地点坐标或不可变地点对象，不回读任意全局状态。
- 地点详情与 A/B 比较保留各分析的日期、来源、口径、缺失和可比性，不生成个人化地点适配度总分。
- 基础设施复用公共交通的交通连通性结果计算 ICI，保留必要的具名结果与共享业务对象。
- 房产新增／坐标变化时取得治安和附近隐患风险并保存档案快照；查询失败仍允许保存，明确不可用。详情不重算、不手动刷新、不自动补算。

## 账号、存储与导航

- 应用继续要求登录；Supabase SDK 提供基础身份，账号记录按当前用户归属在线读写。
- 退出执行基础当前设备退出并返回登录页面，不登记清理参与者、不等待清理证明、不保存清理屏障。
- 不保留账号离线创建、同步或照片待上传队列。普通页面网络失败可由用户在线重新尝试，不自动重放。
- 首页／地图双 Tab、普通子页面、返回式地图选点和明确参数继续保留；取消通用 ShellIntent、贡献发布与组合槽位框架。
- 地图仍显示设施、交通和隐患图层；图层所需业务数据由对应服务提供，不因删除通用贡献协议取消其显示与点击能力。
- 退出不删除预算 JSON 导出；用户主动清空房产回收站仍删除记录与照片。

## 协作与验收

- 跨 Feature 保留必要入口、共享对象、结果含义和失败反馈；移除仅用于通用安全／导航协调的包装，不再机械复制大量声明与结果枚举。
- 使用短文档描述职责、输入输出、依赖和用户可观察行为。历史设计中与本次范围冲突的契约由执行规格安排更新，不能覆盖当前决定。
- 主要通过应用页面入口验证完整旅程，复用 Widget 测试；补充必要的真实 Supabase 与本机存储读写检查。保留公式与数据边界的已有有效测试。
