## 正式开发的数据存储边界

- Supabase 是用户业务记录的权威来源；Flutter 开发前由维护者一次性手动导入本项目所需的全部政府数据，直至项目完成不再导入或更新，且不设置自动同步。
- “本项目所需的全部政府数据”仅指知识库列作功能输入的全部政府开放数据集，不指整个政府开放数据目录。某数据集首次导入失败时，应用必须报告资料暂不可用，不把空表或部分数据作为完整结果。
- SQLite 保存可替换的公共数据缓存、离线“创建”队列和需要查询的轻量记录；设备本地文件保存离线照片等待上传文件，上传成功后可删除本地副本；键值存储仅保存语言、简单界面偏好、缓存数据集日期等小型状态。三者均不替代 Supabase 中的用户业务记录。
- Flutter 的本机存储仅引入 `sqflite`、`path_provider` 和 `shared_preferences` 三项最小依赖，分别服务 SQLite、应用数据文件目录和键值存储；不采用 Drift、ORM、状态管理或后台同步框架，也不实现原生桥接。
- 本项目为一次性的大学交付，重点是 Flutter 与上述数据处理技术的运用。保持技术和数据规模最小，不引入面向长期运营的同步、审计或额外安全机制；已确认的 Supabase 账号隔离和 RLS 仍为基础要求。
- 不可修改提交稿所承诺的地图、收藏、隐患、预算和房产能力见 [submission_commitments.md](./submission_commitments.md)。其中的前台同步、离线创建队列、照片待传和可见回收站属于交付要求，不因“最小技术边界”而省略。

## Agent 判断规则

- “能在界面看到”不等于“能跨重启保留”。
- “上传云端”不等于“支持换设备恢复”；收藏当前只有上行同步。
- 公共分析数据的本机缓存不等于用户数据持久化。
- 退出登录当前不会清理多数业务内存；处理账号切换时必须显式考虑数据泄漏。
