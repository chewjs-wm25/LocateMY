# 已知缺口与不可误判项

## 当前工作树基线

- 截至 2026-09-13，当前 `Rework` 分支的 `lib/` 仅有最小启动页 `main.dart` 与 Supabase 配置；知识库引用的历史原型页面位于 `Prototype` 分支。设计文档不能把历史原型审计写成 `Rework` 当前分支已存在的页面。
- 已确认 Supabase 采用前向迁移：最终以坐标为核心的 `user_saved_locations`、隐患公共可读且仅作者可管理、隐患状态 `pending/resolved` 为契约；只有确认旧表存在数据时，`user_saved_regions` 才做一次性兼容迁移，不能继续作为长期接口。

## 已确认契约与当前迁移的剩余差异

以下差异均已由产品资料或提交承诺确定方向，但当前迁移仍未对齐；它们会影响设计文档中的接口、数据字段和验收条件，需在正式 schema/接口设计时逐项处理：

- `crowdsourced_hazards` 仍允许 `verified`/`rejected`，只有作者可读，且 `title` 可为空、没有五类类型约束；还没有每账户每报告一票、可撤回的投票表。
- `user_budget_scenarios` 缺少生活篮子调整、月净收入和当前评估预案语义，金额默认 `0`，无法区分未填写与明确 RM 0；名称和金额约束也未表达完整。
- `user_property_inspections` 只有单一 `rating`、JSON 和 `image_urls`，没有明确的四项实勘评分、坐标、风险快照/采集时间、私有照片元数据、回收站语义或 Storage 权限契约。
- 政府镜像当前授予客户端较宽的 DML 权限，迁移还注册了自动同步任务；这与“维护者一次性导入、客户端只读、项目期间不自动更新”的数据边界冲突。
- `user_ici_preferences` 仍是安全/交通/教育/医疗/设施五列，产品确认的账户评估偏好应是安全、成本、日常便利、公共交通可达性和基础设施；两者不能混为同一对象。

## 可见但无功能

- 生活成本“查看商家”。
- 账户“搬迁评估历史”。
- 账户两条 Saved Comparisons。
- 账户 My Comments 与 Liked Areas。
- 周边设施条目右箭头与“其他 N 个地点”。
- 治安页 `and N more properties...` 文本。

## 只改变外观、不影响业务

- 账户 Default Location 开关。
- Verified User 徽章固定显示，不能证明邮箱已验证。

## 原型或模拟内容

- 当前代码展示 3 条预设房产；房产新增、编辑、照片、详情、对比和回收站均尚未成为正式持久化能力，但这些能力已由提交承诺基线锁定。
- 房产照片是 mock 对象和占位图，不是真实设备照片或云端文件。
- 房产安全分和附近隐患数是记录字段示例，没有当前公式或数据服务。
- 隐患提交、公共图层、投票和“我的报告”尚为页面示例，不代表远端用户数据；这些能力已由提交承诺基线锁定。
- 现有远端隐患读取权限仍与“登录用户公开可读、创建者可写”承诺不一致；正式实现前必须修正，不能以仅显示本人报告替代公共图层。
- 登录、注册、账户资料和验证徽章是演示内容，不代表认证服务。
- 首页宏观指标仍包含示例数据，尚未完成政府数据同步接入。

## 地点契约不一致

- 治安和公共交通无选点时使用吉隆坡；基础设施无选点时使用 Petaling；生活成本可使用吉隆坡/新山默认名称。

## 原型与目标之间的边界

- 当前示意地图、预设地点、固定隐患列表和房产 fixture 只用于表达 UI 结构，不应作为真实数据功能验收。
- 生活成本、交通、基础设施、社会经济和个人化适配度的公式是研究/重开发口径；原型中的数值不能代表正式数据服务已接入。
- 公共交通原型列表最多保留 30 站；研究模型的统计范围和评分规则见交通/基础设施事实源，二者不能混同。

## 明确不存在

- 独立气候与水灾页面、天气预报、水位监控、实时洪水警报、历史降雨页面。
- Magic Link、游客模式和忘记密码页面。
- GPS 当前定位与离线地图。
- 设施详情、路线、营业时间和评分。
- 公共交通路线几何、班次与运营时间。
