# LocateMY 架构：MVVM 结构

## 概述
LocateMY 遵循模型-视图-视图模型 (MVVM) 架构模式，以确保关注点分离、可维护性和可测试性。

## 分层

### 1. 视图层 (View Layer - `docs/view/`)
- **职责**：UI 渲染和用户交互。
- **技术**：Flutter Widget。
- **通信**：观察来自视图模型的状态。向视图模型发送命令/事件。

### 2. 视图模型层 (ViewModel Layer - `docs/viewmodel/`)
- **职责**：为视图提供业务逻辑、状态管理和数据转换。
- **技术**：`ChangeNotifier`, `StateNotifier`, 或 `Bloc/Cubit`。
- **通信**：与仓库层交互以获取数据。向视图层暴露响应式状态。

### 3. 模型层 (Model Layer - `docs/model/`)
- **职责**：数据实体、DTO（数据传输对象）和领域逻辑。
- **技术**：使用 `json_serializable` 或 `freezed` 的 Dart 类。
- **通信**：由仓库层和视图模型层用于传递结构化数据。

### 4. 仓库层 (Repository Layer - `docs/repository/`)
- **职责**：数据源抽象。
- **技术**：Supabase 客户端，用于 Data.gov.my 的 Http/Dio。
- **通信**：从远程 API 或本地存储获取数据。向视图模型层返回模型。

## 数据流
1. 用户在**视图层**触发操作。
2. **视图层**调用**视图模型层**中的方法。
3. **视图模型层**向**仓库层**请求数据。
4. **仓库层**从 **API/数据库** 获取数据，并解析为**模型**。
5. **视图模型层**接收**模型**，并将其转换为 **UI 状态**。
6. **视图层**根据 **UI 状态** 自动重建。
