# 吉隆坡交通分缺失原因及修改

复现条件：吉隆坡中心坐标 3.139, 101.6869，分析日期 2026-09-18。城市名称本身不是评分范围，移动坐标会改变结果。

数据库实际读到 49 个站点、24 条有效路线、最近站约 192 米，但旧交通分为空，原因是：

- 怡保及芙蓉 A/B 三个 feed 的服务日期不覆盖当天；旧规则要求全国 16 feed 全部可用，因此其他城市的资料影响吉隆坡评分。
- 最新批次的固定参照网格只准备了 2026-09-17 的数据，2026-09-18 没有密度和路线百分位。

修改后，部分 feed 可用且范围内有站点与有效路线即可评分。有同日期参照网格时沿用原 50% 距离、25% 密度、25% 路线公式；缺少网格时只计算距离项并归一化，明确显示“部分交通分，仅距离项”，不以零填补缺失项，也不借用其他日期。

相同真实查询现在得到 **87/100**，约为 `100 × (1 − 192 / 1500)`，数据库使用未取整距离计算。它是距离项的部分读数，不能解释为完整交通覆盖分。单点与 A/B 显示部分分数及缺项说明，A/B 不计算部分分数差异。ICI 复用此分数并保留部分资料提示。完全没有可用来源、范围内没有站点或没有有效路线时仍不可评分。

验证：交通及基础设施 56 项自动测试通过；开发 Supabase 的事务回滚 SQL 回归通过，包括完整公式、部分 feed 评分、缺网格距离评分、空站点/空服务和来源校验；静态分析通过；debug APK 构建通过。数据库 migration 已应用至当前开发项目。
