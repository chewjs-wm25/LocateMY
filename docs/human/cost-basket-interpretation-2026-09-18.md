# 核心市场篮子月支出核查

核查日期：2026-09-18。范围：产品定义、生产计算、页面文案及当前线上公共价格输入；未修改公式、篮子版本或页面。

## 结论

用户认为 RM78.63/月不可能代表一个人的完整月生活开销，这个判断正确。现有指标只计算项目设定的固定商品清单，数量不是经验证的完整生活需求；即使 11 项全部有价格，也不能解释为完整餐饮费、最低生活费或完整个人生活预算。页面的“单身成年人估算”和“核心市场篮子估算月支出”容易让人高估其覆盖范围，属于表达不足，而不是用户对现实开销的判断错误。

未发现生产计算将月金额重复除以 12、或将指数误当金额的问题。但本次未复现用户所见的 RM78.63，不能认定这个具体金额已核验正确。

## 金额实际代表什么

事实源为 [生活篮子 v1](../knowledge_base/locatemy_product/cost_basket_v1.md) 和 [生活成本模型](../knowledge_base/locatemy_product/features/cost_of_living.md)。固定月数量如下：

| 商品 | 固定月数量 |
| --- | --- |
| 鸡肉 | 2 kg |
| 木瓜 | 2 kg |
| A 级鸡蛋 | 30 粒 |
| Dutch Lady 鲜奶 | 4 L |
| Gardenia 面包 | 4 包，每包 400 g |
| 指定品牌大米 | 5 kg（10 kg 包装 × 0.5） |
| 袋装食用油 | 2 kg |
| 糖 | 1 kg |
| 盐 | 约 350 g |
| 指定咖啡粉 | 180 g |
| Sunlight 洗涤剂 | 1 L |

这些是项目产品假设，不是官方营养建议、完整消费清单或官方消费权重。清单没有覆盖全部食材、外食、水电、通信等日常开销，住房和交通也不在其中。

生产代码先把每个可用月份的可观测商品价格乘以固定数量后相加，再对可用月份取平均：

```text
ObservedSpend12 = average over available months {
  sum over items with both local and national prices { quantity × local price }
}
```

商品本地价格由商户内部观测中位数、再对商户中位数取中位数得到。缺失商品被剔除，不补价。因此小金额既可能来自清单范围窄，也可能来自观测缺项；金额下降不能直接解释为现实生活变便宜。

个人预案金额另算为：可观测篮子金额 + 用户额外生活开销 + 住房 + 交通。住房和交通未填写时不能计算；即使填写了，用户仍需在额外生活开销中自行覆盖清单之外的实际开销。

指数则是另一项无金额单位的相对价格读数：每月同组商品的本地金额 ÷ 全国基准金额 × 100，再对月份取平均。100 表示该商品子集与全国基准相同，并不代表 RM100/月。

直接以 `W.P. Kuala Lumpur / Kuala Lumpur` 调用当前 RPC 返回零个观测月份：商户维表的 district 使用上述分区名称，成本服务则把地理解析得到的行政区名称原样传入 RPC。两者存在名称／粒度衔接风险，需要结合具体坐标核验；本次不擅自把分区合并为行政区，也不假定页面地点标题就是实际取数分区。

这意味着，当前输入无法证明用户看到的 RM78.63 的来源与正确性。精确追溯仍需要该次页面对应的坐标、实际解析分区、应用版本及缓存输入。旧缓存或版本差异只是待验证可能，尚不能确认为原因。

## 文案建议（尚未实施）

主标题建议为“固定商品篮子参考金额”；资料缺项时为“部分商品篮子参考金额”，单位仍可使用 RM/月。

说明建议：

> 按项目预设数量估算所列商品的月均购买金额，仅计有价格资料的项目。不代表一个月所需的全部食品或生活开销。

缺项提示应明确说明“缺少价格的商品未计入，金额不代表完整 11 项篮子”，而不只提示部分指数和预算压力。

如产品目标是估算真实月生活费，则需要另行设计并批准更完整的篮子、数量依据及缺项处理；不能通过调整现有标题或任意放大金额达成，也不能直接改写冻结的 v1。
