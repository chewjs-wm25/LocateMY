1. Results, responsibilities and frozen boundaries

Definition of Done (DoD). B has provided the entire section 3 at the only public entrance SUITABILITY-001 Statement; the shell can combine single point/A-B results with the same fake. The real Adapter is proved in Section 5 to have the same account complete five preferences, current plan and five-dimensional input to form an interpretable 0–100 Readings; missing front/dimensions and low-priority renormalization are presented faithfully; A/B are only juxtaposed but not sorted; changes in scope, location, preference, or current version do not publish old results. Completion does not include Widgets, SDKs, SQL, or test implementations.

  • Opened account can see explainable to a legitimate location 0–100 Personalize your readings, or know exactly whether it's preferences, current plans, or which dimension is blocking results. It is not an objective livability score, an official rating, a winner, or a recommendation.
  • The five-dimensional fixed order is: safety, cost, daily convenience, public transportation accessibility, and infrastructure. The main reading is fixed as safety index, personal budget pressure conversion score, 2 km five-category confirmed facility coverage conversion score, transportation connectivity score and neutral 5/5/5 ICI。
  • A/B are calculated individually and then the raw readings are displayed side by side only when common context is compatible; no numerical differences, rankings, winners or automatic relocation suggestions are ever generated.

4. Fixed business semantics, status and sequence

theme Immutable collaboration semantics
prefix If there is no legal location, non-opened scope, different account complete preferences or no current, prerequisite missing will be returned first; default values, drafts, other accounts/plans will not be requested or spliced.
Five-dimensional conversion Safety directly uses the safety index; the cost is 100 − clamp(PersonalBudgetBurden(%), 0, 100); daily convenience uses 100 × confirmed covered-category count ÷ 5; traffic directly uses connectivity score; infrastructure directly uses neutral ICI. All ranges are 0–100, and specific formulas can only be found in the knowledge base.
Gating Preference 1–3 is low,4–6 middle,7–10 high. If either medium or high is unavailable, the total score will not be displayed; if low is unavailable, it can be excluded and explained. Explicit zero is available, unknown/partial/unavailable/no route is non-zero.
renormalization Weight multiplier for each available dimension =preference ÷ 5;Only the weighted average of available dimensions. All dimensions are unavailable or have zero available weights, and the fixed text is "Personalized location suitability is temporarily unavailable: There are currently no available evaluation dimensions."
stale Stale readings that are explicitly available from upstream can participate and warnings must be retained; partial or unavailable does not become available due to the existence of cache.
A/B Comparable only when the available, included/excluded sets at both ends are consistent, the same account has the same preference/current/rule version, and the upstream model, basket/category mapping, boundary/reference group of each included dimension is compatible with integrity. Source dates/stale may differ but need to be disclosed side by side; any incomparability is incomparable.
life cycle Preference/current/location/upstream input version or scope changes immediately invalidate old requests; shutdown starts freeing up private coverage/coverage. Public upstream results can survive their Owner, but cannot be recombined with old account inputs.

Implementation sequence: B first merges into the only entrance,SUITABILITY-001 Declaration and minimum fake; each upstream/shell can be connected with fake in parallel; B then connects to the public interface; finally press FLOW-02, 03, 07 for joint debugging.
