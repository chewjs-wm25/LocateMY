# LocateMY 项目精简：最小账号、在线记录与普通 Flutter 导航

## Problem Statement

LocateMY 是一次性的大学项目，重点应是 Flutter UI、KV、SQLite、Datafile 和 Supabase 的数据储存与调用。目前自建会话管理、账户范围状态机、跨 Feature 私有数据清理、持久化清理屏障及通用导航／贡献框架已成为多个业务模块的共同依赖，大幅增加开发、联调和测试成本，影响项目完成。

复杂度也存在于尚未实现的设计中：收藏离线同步、照片待上传、跨重启房产草稿，以及五项账户评估偏好和个人化地点适配度总分。项目负责人明确允许修改已开发代码和已批准设计，目标是删除额外机制，同时保留核心业务与课程技术展示。

## Solution

账号缩减为邮箱密码注册、登录、退出、SDK 默认保持登录和读取当前用户。应用继续要求登录；账号业务记录只在线读写 Supabase，保留简单的记录归属权限。删除项目自行构建的安全协调和离线同步机制，使用普通 Flutter 路由、页面传参和具名业务服务。

保留首页、地图、六类分析、A/B 比较、收藏、预算、隐患及房产基本能力；删除五项账户评估偏好、个人化地点适配度总分和跨重启房产草稿。房产回收站／恢复明确保留。档案风险快照仅新增或坐标变化时重算；风险查询失败仍允许保存，明确标记不可用。

SQLite 展示公共分析缓存，KV 保存语言与简单设置，Datafile 展示预算预案 JSON 导出与读取。通过应用页面的外部行为验收，辅以少量真实 Supabase 和本机存储检查。

## User Stories

1. 作为学生开发者，我希望优先完成 Flutter UI 和数据使用，以便在大学项目中展示课程重点。
2. 作为学生开发者，我希望删除自建安全协调模块，以便业务开发不再等待清理协议联调。
3. 作为学生开发者，我希望可以调整已有实现和设计，以便已投入的工作不阻碍精简。
4. 作为使用者，我希望用邮箱和密码注册，以便创建可保存业务记录的账号。
5. 作为使用者，我希望注册不要求邮箱确认，以便直接使用应用。
6. 作为使用者，我希望通过邮箱密码登录，并看到普通加载和错误反馈，以便知道操作结果。
7. 作为使用者，我希望 SDK 默认保持登录，以便重启后不必每次重新输入账号。
8. 作为使用者，我希望未登录时看到登录入口，以便应用保持一种明确的使用方式。
9. 作为使用者，我希望账户页显示真实邮箱，以便知道当前使用哪个账号。
10. 作为使用者，我希望退出当前设备后回到登录页，以便结束本次登录。
11. 作为使用者，我希望退出不进入清理恢复页面，以便普通退出流程容易理解。
12. 作为使用者，我希望换账号后按当前身份读取业务记录，以便记录不会被错归到另一个账号。
13. 作为使用者，我希望在首页和地图间切换并正常返回，以便完成主要使用旅程。
14. 作为使用者，我希望切换中英文且重启保留选择，以便使用熟悉的语言。
15. 作为使用者，我希望查看首页宏观指标、来源和数据日期，以便理解信息的新旧。
16. 作为使用者，我希望浏览地图、搜索马来西亚地点并选点，以便选择分析位置。
17. 作为使用者，我希望查看合法地点的六类分析，以便分别理解生活成本、治安、社会经济、基础设施、设施和交通。
18. 作为使用者，我希望并列比较地点 A/B，以便查看相同口径的差异。
19. 作为使用者，我希望缺失、缓存和不可比较状态明确显示，以便不把未知当成零或完整结果。
20. 作为使用者，我希望在线保存、读取、选择和删除收藏地点，以便复用选址。
21. 作为使用者，我希望登录同一账号后在线读取云端收藏，以便不依赖设备同步队列。
22. 作为使用者，我希望在线管理预算预案的名称和金额，以便保存自己的预算场景。
23. 作为使用者，我希望选择当前预算预案后相关读数更新，以便查看正确的预算压力和收入位置。
24. 作为使用者，我希望无预案时仍能使用临时 CPI 等效换算，以便尝试金额而不保存。
25. 作为使用者，我希望将已保存预算预案导出为本机 JSON，以便查看文件形式的数据副本。
26. 作为使用者，我希望在应用中读取预算 JSON 并展示内容，以便确认文件确实可以使用。
27. 作为使用者，我希望导出文件跨重启和退出保留，以便文件不会因账号退出被删除。
28. 作为使用者，我希望损坏或不支持的 JSON 有明确反馈，以便知道读取失败且云端记录未被改动。
29. 作为使用者，我希望发布五类隐患并查看地图图层和详情，以便报告和了解公共隐患。
30. 作为使用者，我希望管理自己的隐患处理状态和删除自己的报告，以便维护本人内容。
31. 作为使用者，我希望持久化赞成、反对或撤回投票，以便表达意见且不重复计票。
32. 作为使用者，我希望新增和编辑房产实勘，以便保存价格、地点、现场评分和备注。
33. 作为使用者，我希望从地图返回选点时保留当前表单，以便正常完成录入。
34. 作为使用者，我希望从相机或相册取得真实照片并在线上传，以便为实勘保存视觉记录。
35. 作为使用者，我希望查看档案、详情和两至三份实勘对比，以便比较实际记录。
36. 作为使用者，我希望删除实勘后可在回收站恢复，以便纠正误删。
37. 作为使用者，我希望确认永久清空后删除实勘和照片，以便执行真实业务删除。
38. 作为使用者，我希望档案保存新增或坐标变化时的风险快照，以便理解该地点当时的风险上下文。
39. 作为使用者，我希望普通编辑、详情查看和重启不重新计算风险，以便档案快照保持其含义。
40. 作为使用者，我希望风险查询失败仍可保存实勘，并看到不可用提示，以便不因另一项分析故障丢失录入机会。
41. 作为使用者，我希望坐标变化后不显示冒充新地点风险的旧快照，以便档案的地点和风险一致。
42. 作为使用者，我希望仍能调整三个基础设施 ICI 权重，以便查看单点综合覆盖的需求变化。
43. 作为使用者，我希望公共分析可按原有 SQLite 缓存规则读取，以便离线时仍能查看已有公共资料。
44. 作为使用者，我希望联网失败时明确知道账号记录未保存，以便主动重试，而不是等待隐含同步。
45. 作为学生开发者，我希望复用应用入口和已有有效测试，以便避免为已删除的协议建立新的测试框架。

## Implementation Decisions

1. **执行范围。** 本规格执行阶段负责精简既有代码、更新整体架构与未实现 Feature 的必要设计，并删除失效依赖。尚未实现的预算、房产和分析业务不因本规格被要求一次性全部实现；它们后续按这里确定的新边界开发。预算 JSON 的设计和验收条件必须在本次精简中固定，实现随预算 Feature 交付。当前会话仅交付决定与规格，不启动代码重构。
2. **优先级。** 2026-09-17 项目负责人逐项确认的范围及 ADR 0017 优先于冲突的旧系统基线、Development Contract 和提交承诺。只取消明确决定删除的能力；保留业务、数据口径及来源不会被旧文档误排除。
3. **账号边界。** Authentication & Session 缩减为账号入口职责：调用 Supabase 注册、登录、当前设备退出，消费 SDK 当前用户和默认身份变化。关闭注册邮箱确认，删除待验证状态及徽章。保留现有表单必要校验、加载和普通失败反馈；可选用户名不成为登录成功的前提。
4. **删除自建会话协调。** 删除启动时项目额外的远端重复身份核验、自定义失效计时、会话恢复／不可用复杂状态与注册资料专用恢复流程。SDK 内部认证、token、刷新和默认持久化仍由 SDK 处理，不重新实现。
5. **删除 Account Privacy。** 删除独立模块、范围 open／closing／closed 状态机、participant 登记、关闭证明、逐 Owner 清理重试、持久化屏障及其公开依赖。Auth、Shell、Map、Hazard 及所有设计消费者均停止引用；公共设施与其他公共分析也停止消费账户 scope token。
6. **普通页面生命周期。** 基础退出成功后结束业务页面并显示登录页。新账号重新建立普通页面状态并按当前用户加载记录；使用 Widget 生命周期处理已销毁页面的响应。失败给出普通退出重试，不建立跨 Feature 封锁、清理证明或恢复屏障。退出不删除云端记录、回收站或预算 JSON。
7. **导航与组合。** Application Shell 缩减为应用装配、登录入口、首页／地图双 Tab、普通路由和语言接线。取消通用导航意图、贡献发布、组合槽位与多层结果包装；业务页面通过明确参数和具名服务组合内容。必要业务对象、结果可用性和共享服务保留，不为形式保留空层、包装类或庞大的逐声明契约。
8. **保留 Feature 责任。** 保留首页、地图／地点、生活成本／预算、治安、社会经济、基础设施、周边设施、公共交通、隐患、房产和最小账户中心职责。地理语境仍作为共享业务服务提供正确地区口径。现有地图图层、点击行为和分析入口不会因删除通用框架消失。
9. **取消总分与偏好。** 删除 Personalized Location Suitability Feature、`MAP-07` 以及 `ACCOUNT-08` 五项评估偏好设置、计算、保存与数据依赖。`AUTH-03` 验证界面排除。保留 `ACCOUNT-09` 当前预算预案，以及医疗／教育／交通三个账户级 ICI 权重；它们在线保存，默认 5，只影响基础设施单点 ICI，摘要及 A/B 使用中性权重。
10. **在线账号记录。** 收藏、预算、隐患、投票、实勘和照片只在线读写 Supabase；同账户登录后直接读取云端记录。删除收藏私有 SQLite 缓存、离线创建、双向同步、照片待传、自动重放和相关队列状态。网络失败给出未保存或未上传反馈，可在当前页面在线重新尝试。
11. **房产表单。** 删除跨重启草稿及草稿照片持久化。当前页面输入和返回式地图选点仍保留。维持现有实勘字段、四项评分平均、档案、详情与 2–3 项对比；不以 mock 或启动示例替代真实数据。
12. **档案风险。** 仅在新增或实际改变坐标时请求并保存风险组；查询失败、缺失或不完整仍允许保存，快照明确不可用。修改普通字段、查看详情、重启不重算，不提供手动刷新或自动补算。坐标变化后不能沿用旧地点风险作为新地点读数；保留可用性和采集时间，遵守既有州级治安及附近 pending 隐患统计口径。
13. **照片与回收站。** 保留相机／相册、压缩、每份最多 20 张、说明、封面和在线删除，文件与元数据归属实勘账户。照片在线上传，无持久化待传或后台同步。删除实勘先进入回收站并保留照片，可恢复；确认永久清空时删除记录及 Storage 照片。部分失败反馈真实，可在线重新尝试；这是用户主动业务删除，不是退出清理功能。
14. **本机存储。** KV 保存语言和简单设置；SQLite 保存公共分析缓存并显示日期、来源和旧缓存状态；沿用现有最小存储依赖。已有 SDK 登录状态下，公共资料可按缓存规则离线读取；账号写入不因此离线排队。保留政府数据一次性导入和现有 OSM／GTFS 来源边界。
15. **Datafile。** 新增 `COST-05` 预算 JSON 导出及读取。导出已保存预案的标识、名称、业务金额字段与导出时间，采用一个带明确格式版本的 JSON 文档，保存于应用文件目录。读取只展示导出副本，不创建或更新云端预案；缺失、损坏或不支持版本明确失败，金额缺失与零区分。文件跨重启与退出保留；不新增分享、云端导入或自动同步。
16. **Supabase 与数据模型。** 基础 SDK 认证、当前用户标识、简单 owner 归属 RLS、公开隐患读取和公共政府数据只读边界保留。取消能力相关的业务对象和本机队列停止被使用；按现状检查后用向前 migration 调整废弃对象与风险快照可用性，不删除历史 migration 来重置环境。数据库对象存在不代表对应 Flutter Feature 已实现。
17. **实施与完成。** 先调整账号、应用入口和路由；同步移除既有地图、设施、隐患与其他消费者依赖；再整理本机存储、已排除能力和必要设计。最终既有应用可运行，账号与存储边界符合本规格，失效 import／接口／测试已删除，产品资料和架构索引不再要求旧协议。未实现 Feature 明确标注设计目标与开发状态，禁止以成功占位宣称交付。

## Testing Decisions

- 用户已确认最高主要 seam 为**应用页面入口**。复用已有应用 Widget 测试基础，以可见内容、用户动作、导航结果、保存／读取与失败反馈断言外部行为；不测私有方法、内部状态枚举或包装类存在。
- 测试范围包括基础账号入口、普通导航与语言、地图及收藏、已有分析／图层、隐患和本机缓存。预算 JSON、房产、回收站、风险时机及 ICI 权重的用例固定为后续对应 Feature 的验收条件；尚未实现的功能不会通过 fake 成功被宣称完成。
- 主旅程覆盖注册／登录、重启保持登录、退出／换账号后读取正确记录、首页／地图返回、合法地点与 A/B、在线记录及普通网络失败。不要求多设备会话撤销、重复远端身份验证、私有清理证明或清理中重启恢复。
- 本机检查用真实可控的 KV、SQLite 和临时文件读写验证跨重启保留、公共缓存、JSON 字段／缺失值、损坏与版本不支持；在应用可观察行为上验收，不为每种存储建立新通用框架。
- 少量真实 Supabase smoke 验证 SDK 注册／登录／当前设备退出、记录归属和所保留的读写行为。后续照片与回收站实装时验证真实 Storage 与元数据；使用本地测试凭据，账号和密码不进入日志或版本控制。
- 房产风险重点验证：新增与实际坐标变化才计算；普通字段编辑、详情和重启不计算；风险失败仍保存且明确不可用；旧地点快照不冒充新地点；不存在自动补算或手动刷新入口。
- 回收站验证软删除保留照片、恢复、取消清空无副作用、确认永久清空与部分失败真实反馈。退出不会触发这些业务删除。
- Prior art 为现有应用 Widget／导航／双语测试、地图与隐患页面及公开服务测试、SQLite 存储测试、已有可选 live 测试。可重用正常业务情景，删除仅服务 Account Privacy、自建会话协议和旧通用导航包装的测试与 fake。
- 保留仍有意义的公式、地理口径和数据质量测试。对实际代码重构运行格式检查、静态分析、相关测试和 debug APK 构建；当前文档与规格交付只检查内容、链接和格式，不声称代码测试已通过。

## Out of Scope

- 本次讨论直接启动业务代码重构、变更 live Supabase 或删除远端数据。
- 本规格执行时一次性补齐所有尚未实现的预算、房产及分析 Feature；它们按已确定精简边界继续开发。
- 自建会话管理、跨 Feature 安全协调、私有清理证明、清理恢复、离线账号队列、自动同步和后台重试。
- 邮箱验证界面、五项评估偏好、个人化地点适配度总分、房产跨重启草稿、手动风险刷新和自动补算。
- 新增游客模式、MFA、密码重置、账号注销、设备会话管理、审计或安全存储框架。
- 预算 JSON 写回云端、通用导入／分享／备份系统、房产照片导出。
- 改写既有分析公式、改变地理口径、删除核心分析／地图／投票能力、删除回收站／恢复或删除风险档案本身。
- 修改原始大学提交稿，或将尚未实现的设计描述为已完成产品。
