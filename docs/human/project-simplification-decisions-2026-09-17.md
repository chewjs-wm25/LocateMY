# LocateMY 精简决定与待定范围

## 已确认原则

1. 项目以一次性的大学交付为目标，重点是 Flutter UI、KV、SQLite、Datafile 与 Supabase 的实际使用。
2. 保留邮箱密码注册、登录、退出、SDK 默认保持登录和当前用户身份，以及 Supabase 上简单的记录归属权限。取消邮箱确认要求及其界面、自建会话管理、独立 Account Privacy 和跨模块数据清理协议。
3. 账号记录只在线读写 Supabase，取消离线创建队列、自动同步和照片待上传队列。
4. 允许全面审查现有 Feature/shared module，已开发或已批准不构成保留理由；具体删减采用下列已确认范围。

## 已确认的具体范围

- 继续要求登录后进入主应用。
- 采用普通 Flutter 路由、页面传参和具名业务服务，取消通用导航意图、组合槽位与贡献发布框架；保留必要共享对象和职责边界。
- 删除房产跨重启草稿和个人化地点适配度总分。
- 保留地图选址、六类分析、A/B 比较、收藏、预算、隐患，以及房产新增、编辑、照片、详情与对比。
- 保留房产回收站与恢复功能；房产风险数据保存于档案，只在新增或坐标变化时重新计算。取消手动风险刷新和查看详情时重算。
- 预算预案可导出本机 JSON，并在应用中读取展示。文件不自动同步，不替代云端记录，退出不删除；本轮没有增加 JSON 导入云端或自动分享功能。
- SQLite 展示公共分析缓存；KV 保存语言与简单设置。
- 删除五项账户评估偏好及其设置、保存逻辑和数据依赖；保留三个基础设施 ICI 权重和当前预算预案。
- 风险输入缺失仍允许保存实勘，明确标记快照不可用；坐标变化后不将旧地点快照当作新地点风险，不提供自动补算。

## 已查明的现状

生产代码已存在 Authentication、Account Privacy、Shell、地图收藏、首页、隐患、周边设施和公共交通能力；预算、房产实勘、账户中心业务和若干分析 Feature 仍有设计但缺少对应生产 Feature 实现。本次只读调查未运行测试，不将代码存在等同于完成验收。

账号复杂度包括启动远端身份复核、自定义失效处理、账户范围状态机、清理参与者和持久化清理屏障。当前生产注册 Auth、Shell、Map、Hazard 四类清理参与者；公共设施查询也依赖账号范围 token。

## 最终验收与交付

2026-09-17 用户已确认整体范围和验收方式，无剩余产品决策待确认。主要从应用页面入口验收注册、登录、重启、退出／换账号、地图分析与收藏、预算及 JSON 文件、隐患和房产完整旅程；复用现有 Widget 测试，辅以少量真实 Supabase、本机 KV、SQLite 和文件读写检查。删除仅为清理屏障、自建会话协调与关闭证明服务的测试。
