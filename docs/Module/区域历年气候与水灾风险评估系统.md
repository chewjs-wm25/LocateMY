# 区域历年气候与水灾风险评估系统

## 1. 模块简介与定位

* **模块名称**：区域历年气候与水灾风险评估系统 (Regional Historical Climate & Flood Risk Assessment System)
* **功能描述**：基于官方历史水灾日志（Data.gov.my / NADMA）与水利灌溉局（JPS）淹没区划图数据，在 Flutter 移动端地图与数据面板中综合展示目标区域的历史水灾发生频次、积水深度、退水速度及季风期降雨分布。同时集成**个人专属“实地验房与房源档案库”**，结合 Supabase 免费 Storage 与 Postgres 数据库，辅助用户进行长期/半永久性搬家选址的风险评估与实地验房决策。

---

## 2. 决策维度剖析与用户价值

* **公共安全与长期居住风险维度（气候水文板块）**：
  * **长期资产与安全保障**：半永久性搬家用户（购房者或长期租客）的核心痛点在于评估目标区域的长期抗洪能力与资产保值度。
  * **雨季黄金看房/验房窗口（Golden Inspection Window）**：结合东北季风（11月-3月）与西南季风（5月-9月）历史降雨规律，Flutter 应用自动提示雨季看房时机，引导用户在风险高发期实地考察周边排涝速度与低洼积水情况。
  * **微观资产决策与档案管理**：宏观数据无法取代具体的房屋防汛细节。通过实地验房档案库，用户能将系统提示的“雨季 Checklist”转化为具体的看房记录与跨房源横向对比。

## 3. 核心数据源与 API / 数据集规范 (100% 免费公开数据)

### 3.1 气象预报与灾害预警 API (`/weather/forecast` 与 `/weather/warning`)
* **数据机构**：马来西亚气象局 (MET Malaysia) / Data.gov.my
* **数据形式**：RESTful Open API (JSON 响应格式，0 成本)
* **API 端点**：
  * 天气预报：`GET https://api.data.gov.my/weather/forecast`
  * 灾害预警：`GET https://api.data.gov.my/weather/warning`
* **关键提取字段**：`location_category`, `location_code`, `summary_when`, `warning_type`, `date`
* **更新机制**：实时 / 每日多次更新。

### 3.2 历史气象与降雨分布数据集 (`climate_weather_stats`)
* **数据机构**：MET Malaysia / Data.gov.my Data Catalogue
* **关键提取字段**：`state`, `district`, `month`, `avg_monthly_rainfall_mm`, `heavy_rain_days`
* **应用场景**：提取东北季风（11月-3月）与西南季风（5月-9月）期间的高风险月份（`monsoon_risk_months`）。

### 3.3 JPS 淹没区划与水文监测数据集
* **数据机构**：水利灌溉局 (JPS) / MyWater GeoPortal / Public InfoBanjir
* **获取渠道 / 端点**：JPS SPDG Portal (`spdg.water.gov.my`) / `publicinfobanjir.water.gov.my` 开放接口
* **关键提取字段**：`ARI_return_period` (重现期), `inundation_depth_zone` (积水深度区间), `water_level_m`
* **应用场景**：导出历史平均退水时间（`drainage_recovery_hours`）。

### 3.4 NADMA 与 OpenDOSM 历史水灾事件日志
* **数据机构**：国家灾害管理局 (NADMA) / 马来西亚统计局 (OpenDOSM)
* **关键提取字段**：`event_id`, `event_date`, `poskod`, `mukim_id`, `district`, `evacuation_count`, `water_depth_cm`
* **应用场景**：计算过去 5 年的水灾发生总频次（`events_count_5yr`）及平均积水深度（`avg_water_depth_cm`）。

## 4. 空间对齐与水灾综合风险指数评分模型

### 4.1 空间编码转换 (Supabase PostGIS)
在 Supabase PostgreSQL 中启用免费 `postgis` 扩展，将历史水灾多边形数据离线映射归因至 Poskod / Mukim 维度的空间表。Flutter 前端发起查询时，依据用户定位直接毫秒级检索目标 Poskod 的静态风险数据。

### 4.2 水灾综合风险指数评分模型 ($R_{\text{flood}, i}$)
定义目标区域 $i$（以 Poskod 或 Mukim 为单位）的综合水灾风险指数 $R_{\text{flood}, i}$：

$$R_{\text{flood}, i} = w_1 \cdot \min\left(1, \frac{N_{5\text{yr}, i}}{N_{\max}}\right) + w_2 \cdot \min\left(1, \frac{D_{\text{avg}, i}}{D_{\max}}\right) + w_3 \cdot \min\left(1, \frac{T_{\text{rec}, i}}{T_{\max}}\right) + w_4 \cdot H_{\text{zone}, i}$$

其中：
* $N_{5\text{yr}, i}$ 为过去 5 年内该区域水灾发生频次（`events_count_5yr`）；
* $D_{\text{avg}, i}$ 为历史平均积水深度（`avg_water_depth_cm`）；
* $T_{\text{rec}, i}$ 为平均排涝退水恢复时间（`drainage_recovery_hours`）；
* $H_{\text{zone}, i}$ 为 JPS 淹没区划图定义的风险等级权重（如 100 年一遇 Zone 取 0.5，50 年一遇 Zone 取 1.0）；
* $w_1, w_2, w_3, w_4$ 为各因子权重系数，满足 $\sum w_k = 1$。

## 5. 交互式扩展模块：个人专属“实地验房与房源档案库” (Flutter + Supabase)

### 5.1 业务逻辑与系统结合点
用户实地考察意向房源时，可在 Flutter 应用中建立房源档案，输入租金/售价、记录防汛设施打分、使用手机摄像头实拍上传照片并记录验房笔记。系统自动将用户报价与 NAPIC 发布的该县市场均价对比，提示租金折溢价。

### 5.2 0 成本技术方案
* **前端**：Flutter + `image_picker` + `flutter_map`。
* **后端**：Supabase Free Plan（PostgreSQL 数据库 + 免费 1GB Supabase Storage `inspection_photos` Bucket + Supabase Auth 鉴权），**无需绑定信用卡**。

### 5.3 数据库 Schema 与 RLS 安全策略设计

#### 数据表定义：`user_property_inspections`

```sql
CREATE TYPE property_listing_type AS ENUM ('RENT', 'BUY');

CREATE TABLE user_property_inspections (
  inspection_id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  property_name VARCHAR(128) NOT NULL,
  address_line TEXT,
  poskod VARCHAR(10) NOT NULL,
  latitude DOUBLE PRECISION,
  longitude DOUBLE PRECISION,
  quoted_price DECIMAL(10,2) NOT NULL,
  property_type property_listing_type NOT NULL DEFAULT 'RENT',
  -- Checklist 打分 JSONB: {"drainage": 4, "basement": 5, "dampness": 3, "road": 4}
  checklist_scores JSONB NOT NULL DEFAULT '{"drainage": 3, "basement": 3, "dampness": 3, "road": 3}'::jsonb,
  photo_urls TEXT[] DEFAULT ARRAY[]::TEXT[],
  inspection_notes TEXT,
  is_archived BOOLEAN NOT NULL DEFAULT FALSE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_property_inspections_user ON user_property_inspections(user_id);

-- 行级安全策略 (RLS)
ALTER TABLE user_property_inspections ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can fully manage their own property inspections"
  ON user_property_inspections
  FOR ALL
  USING (auth.uid() = user_id)
  WITH CHECK (auth.uid() = user_id);
```

### 5.4 Flutter 客户端集成与 CRUD 操作规范

```dart
import 'package:flutter/material.dart';
import 'package:supabase_flutter/supabase_flutter.dart';
import 'package:image_picker/image_picker.dart';

class PropertyInspectionService {
  final _supabase = Supabase.instance.client;

  // 1. Create: 上传验房照片并创建房源档案
  Future<void> createInspection({
    required String propertyName,
    required String addressLine,
    required String poskod,
    required double? lat,
    required double? lng,
    required double quotedPrice,
    required String propertyType,
    required Map<String, int> checklistScores,
    required List<XFile> photos,
    String? notes,
  }) async {
    final user = _supabase.auth.currentUser;
    if (user == null) throw Exception("请先登录");

    List<String> uploadedUrls = [];
    for (var photo in photos) {
      final bytes = await photo.readAsBytes();
      final fileExt = photo.name.split('.').last;
      final fileName = '${user.id}/${DateTime.now().millisecondsSinceEpoch}_${photo.name}';

      // 上传至 Supabase 免费 Storage
      await _supabase.storage.from('inspection_photos').uploadBinary(
        fileName,
        bytes,
        fileOptions: FileOptions(contentType: 'image/$fileExt'),
      );
      final url = _supabase.storage.from('inspection_photos').getPublicUrl(fileName);
      uploadedUrls.add(url);
    }

    // 写入 PostgreSQL
    await _supabase.from('user_property_inspections').insert({
      'user_id': user.id,
      'property_name': propertyName,
      'address_line': addressLine,
      'poskod': poskod,
      'latitude': lat,
      'longitude': lng,
      'quoted_price': quotedPrice,
      'property_type': propertyType,
      'checklist_scores': checklistScores,
      'photo_urls': uploadedUrls,
      'inspection_notes': notes,
    });
  }

  // 2. Read: 读取当前用户的未归档验房档案列表
  Future<List<Map<String, dynamic>>> fetchInspections() async {
    final user = _supabase.auth.currentUser;
    if (user == null) return [];

    final response = await _supabase
        .from('user_property_inspections')
        .select()
        .eq('user_id', user.id)
        .eq('is_archived', false)
        .order('created_at', ascending: false);

    return List<Map<String, dynamic>>.from(response);
  }

  // 3. Update: 更新验房打分、报价或补充笔记
  Future<void> updateInspection({
    required String inspectionId,
    required double quotedPrice,
    required Map<String, int> checklistScores,
    String? notes,
  }) async {
    await _supabase.from('user_property_inspections').update({
      'quoted_price': quotedPrice,
      'checklist_scores': checklistScores,
      'inspection_notes': notes,
      'updated_at': DateTime.now().toIso8601String(),
    }).eq('inspection_id', inspectionId);
  }

  // 4. Delete: 淘汰/归档房源档案
  Future<void> archiveOrDeleteInspection(String inspectionId, {bool permanent = false}) async {
    if (permanent) {
      await _supabase
          .from('user_property_inspections')
          .delete()
          .eq('inspection_id', inspectionId);
    } else {
      await _supabase
          .from('user_property_inspections')
          .update({'is_archived': true})
          .eq('inspection_id', inspectionId);
    }
  }
}
```
