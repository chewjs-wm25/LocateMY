# 公共交通连通性与站点密度评分引擎

## 1. 模块简介与定位
- **模块名称**：公共交通连通性与站点密度评分引擎 (Public Transit Connectivity & Stop Density Scoring Engine)
- **功能描述**：基于官方 GTFS 静态与实时数据，在 Flutter 移动端计算并可视化展示目标居住点指定半径（如 500 米）内的公共交通站点可达性、线路覆盖丰富度及实时班次到站预测。结合 Supabase PostGIS 免费空间能力与客户端高效计算，为非自驾群体提供出行决策支持。

## 2. 决策维度剖析与用户价值
- **交通通勤与公共交通连通性维度**：
  - 通勤时间与出行成本直接影响日常生活幸福感。
  - 公共交通网络的覆盖密度（如 Prasarana 轨交 MRT/LRT/Monorail、KTMB 铁路及各州 BAS.MY 停靠站点）与实时调度状况，决定了非自驾群体（学生、通勤上班族、无车家庭）的出行便利度。

## 3. 核心数据源与 API 规范 (100% 免费开放数据)

### 3.1 公共交通 GTFS 静态 API (GTFS Static)
- **数据机构**：马来西亚交通部 (Transport Ministry / APAD) / Data.gov.my
- **API 端点**：
  - **马来亚铁道 (KTMB)**：`GET https://api.data.gov.my/gtfs-static/ktmb`
  - **国家基建公司 (Prasarana Rail - 巴生谷 MRT/LRT/Monorail)**：`GET https://api.data.gov.my/gtfs-static/prasarana?category=rail`
  - **各州 BAS.MY 巴士网络**：`GET https://api.data.gov.my/gtfs-static/mybas-johor`（以及 `mybas-ipoh`, `mybas-kangar`, `mybas-seremban` 等城市）
- **关键提取文件与字段**：标准 GTFS ZIP 规范中的 `stops.txt`, `routes.txt`, `trips.txt`
- **更新机制**：定期维护 / 线路变动时更新。
- **费用与限制**：完全公开免费，无需信用卡。

### 3.2 公共交通 GTFS 实时 API (GTFS Realtime)
- **API 端点与格式**：提供车辆实时位置与到站预测 Protocol Buffers / JSON 格式数据（`GET https://api.data.gov.my/gtfs-realtime/...`）。
- **应用场景**：为 Flutter 客户端展示周边站点的实时列车动态与预计到站时间倒计时。

## 4. 算法建模与评分计算机制

### 公共交通可达性得分 ($S_{5, d}$)
基于 GTFS 数据计算目标居所指定步行半径（如 500 米步径）内可达至少一个公共交通站点的覆盖比例 $T_{\text{cov}, d}$：

$$S_{5, d} = T_{\text{cov}, d} \times 100$$

系统进一步结合站点密度（Stop Density）、经过线路丰富度（Route Diversity）与发车频次（Service Frequency）构建加权评分，为非自驾用户提供直观的出行便利指数。

## 5. Flutter 客户端交互与 Supabase 架构集成

### 5.1 技术方案与 0 成本保证
* **前端展示**：
  - `FlutterMap` + `MarkerLayer` 渲染周边 500m 内的轨交与巴士站点图标。
  - `RealtimeTransitCard`：倒计时卡片展示最近站点的下一班车预计到站时间（ETA）。
* **后端与计算 (Supabase Free Tier)**：
  - 将 GTFS `stops` 站点数据导入 Supabase PostgreSQL，利用 PostGIS 空间索引实现快速半径检索（`ST_DWithin`）。
  - **100% 免费，无需信用卡**。

### 5.2 Supabase PostGIS 站点检索 RPC 函数

```sql
-- 免费 PostGIS 存储过程：查询指定坐标 500 米范围内的公共交通站点
CREATE OR REPLACE FUNCTION get_nearby_transit_stops(
  user_lng DOUBLE PRECISION,
  user_lat DOUBLE PRECISION,
  radius_meters DOUBLE PRECISION DEFAULT 500.0
)
RETURNS TABLE (
  stop_id TEXT,
  stop_name TEXT,
  transit_type TEXT,
  distance_meters DOUBLE PRECISION,
  lat DOUBLE PRECISION,
  lng DOUBLE PRECISION
) AS $$
BEGIN
  RETURN QUERY
  SELECT 
    s.id AS stop_id,
    s.name AS stop_name,
    s.type AS transit_type,
    ST_Distance(
      s.geom::geography, 
      ST_SetSRID(ST_Point(user_lng, user_lat), 4326)::geography
    ) AS distance_meters,
    s.latitude AS lat,
    s.longitude AS lng
  FROM transit_stops s
  WHERE ST_DWithin(
    s.geom::geography, 
    ST_SetSRID(ST_Point(user_lng, user_lat), 4326)::geography, 
    radius_meters
  )
  ORDER BY distance_meters ASC;
END;
$$ LANGUAGE plpgsql STABLE;
```

### 5.3 Flutter Dart 集成实现示例

```dart
import 'package:flutter/material.dart';
import 'package:supabase_flutter/supabase_flutter.dart';

class TransitService {
  final _supabase = Supabase.instance.client;

  // 调用 Supabase PostGIS RPC 获取 500m 内站点
  Future<List<Map<String, dynamic>>> fetchNearbyStops({
    required double lat,
    required double lng,
    double radius = 500.0,
  }) async {
    final response = await _supabase.rpc('get_nearby_transit_stops', params: {
      'user_lng': lng,
      'user_lat': lat,
      'radius_meters': radius,
    });
    return List<Map<String, dynamic>>.from(response);
  }
}
```
