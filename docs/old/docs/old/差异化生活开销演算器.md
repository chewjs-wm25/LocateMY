# 差异化生活开销演算器

## 1. 模块简介与定位
- **模块名称**：差异化生活开销演算器 (Differential Cost of Living Calculator)
- **功能描述**：允许用户在 Flutter 移动端输入当前各类别月度支出（住房、食品、公用事业、交通等）及自定义预算项目，系统结合 OpenDOSM 县级 CPI 指数与 PriceCatcher 每日微观物价数据，自动演算新旧住址间的预估开销差额 ($\Delta \text{CoL}_{A \to B}$) 与购买力变动。同时集成**多情景搬家生活开销预案中心**，依托 Supabase 免费版 PostgreSQL 与 Auth 实现多套个性化开销预案的持久化云端存储、同步与横向比对。

## 2. 决策维度剖析与用户价值
- **生活成本与财务压力维度**：
  - 用户不仅需要评估新旧住址之间的住房租售成本，还必须考虑食品饮料、水电燃气及日常消费品的微观物价差异。
  - 各州及县域间通货膨胀率（CPI）的相对波动，直接决定了不同收入阶级（B40 低收入群、M40 中产阶级、T20 高收入群）在迁移后的真实购买力变化。
  - **持久化预算决策**：搬家决策往往伴随多种情景选择（例如：单身租房情景 vs 家庭购房情景）。提供多情景预算 CRUD 管理，使用户能反复比对、动态调校不同搬家预案下的月度收支状况。

## 3. 核心数据源与 API 规范 (100% 免费开放数据)

### 3.1 日常商品价格微观追踪 (`pricecatcher` 与 `lookup_premise`)
- **数据机构**：国内贸易及生活成本部 (KPDN) / OpenDOSM
- **数据内容**：每日追踪全国数千家零售场所（超市、湿巴刹等）的基础商品价格明细。
- **API 端点**：
  - `GET https://api.data.gov.my/data-catalogue?id=pricecatcher`
  - `GET https://api.data.gov.my/data-catalogue?id=lookup_premise`
- **关键提取字段**：`premise_code`, `item_code`, `price`
- **更新机制**：每日更新。Flutter 客户端按需拉取目标住址周边 5 公里半径内场所数据，并在本地 SQLite / 内存中缓存。

### 3.2 通货膨胀与物价指数 (`cpi_core`)
- **数据机构**：马来西亚统计局 (OpenDOSM)
- **数据内容**：县级/州级消费物价指数（CPI 分项指数）。
- **API 端点**：`GET https://api.data.gov.my/opendosm?id=cpi_core`
- **关键提取字段**：`date`, `group`, `index`
- **更新机制**：月度更新。

### 3.3 房产租售扩展数据源 (NAPIC / JPPH)
- **数据机构**：国家房产信息中心 (NAPIC)
- **数据内容**：各县重点社区的平均每平方英尺租金与交易均价（由离线清洗后的公开报表导入 Supabase 或应用打包内置）。

## 4. 数据合成算法与数学建模

### 动态生活开销差异计算模型
定义用户从原住址 $A$ 搬迁至新住址 $B$ 的预计月度开销变化额 $\Delta \text{CoL}_{A \to B}$：

$$\Delta \text{CoL}_{A \to B} = \sum_{c \in C} \left( E_{\text{user}, c} \cdot \frac{I_{B, c}}{I_{A, c}} - E_{\text{user}, c} \right)$$

其中：
- $C = \{\text{住房}, \text{食品饮料}, \text{水电公用}, \text{交通}, \text{其他}\}$ 为消费类别集合。
- $E_{\text{user}, c}$ 为用户输入的原住址月度实际支出。
- $I_{A, c}$ 与 $I_{B, c}$ 为价格指数：
  - **食品饮料类**：系统基于 PriceCatcher 计算两个住址周边 5 公里半径内标准零售篮子的平均价格比值。
  - **住房与公用事业类**：采用 OpenDOSM 提供的县级/州级 CPI 分项指数及 NAPIC 租金指数进行折算。

## 5. 交互式扩展模块：多情景搬家生活开销预案中心 (Flutter + Supabase)

### 5.1 业务逻辑与技术方案
用户可针对不同的生活规划（如“独居极简方案”、“家庭三口育儿方案”、“跨州工作调动方案”）创建多套命名开销预案。
* **Flutter 前端**：采用 `fl_chart` 渲染并排对比柱状图，使用 `Slider` 与 `TextFormField` 提供交互式开销调校。
* **Supabase 后端 (Free Tier)**：在 PostgreSQL 中保存预案配置，通过 Supabase Auth 与 Row Level Security (RLS) 隔离用户隐私，**完全免费且无需信用卡**。

### 5.2 数据库 Schema 与 RLS 安全策略设计

#### 数据表定义：`user_budget_scenarios`

```sql
CREATE TABLE user_budget_scenarios (
  scenario_id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  scenario_name VARCHAR(64) NOT NULL,
  origin_poskod VARCHAR(10) NOT NULL,
  target_poskod VARCHAR(10) NOT NULL,
  housing_expense DECIMAL(10,2) NOT NULL DEFAULT 0.00,
  food_expense DECIMAL(10,2) NOT NULL DEFAULT 0.00,
  utility_expense DECIMAL(10,2) NOT NULL DEFAULT 0.00,
  transport_expense DECIMAL(10,2) NOT NULL DEFAULT 0.00,
  custom_expenses JSONB DEFAULT '[]'::jsonb, -- 扩展自定义消费项: [{"name": "托儿费", "amount": 1200.0}]
  calculated_diff DECIMAL(10,2) DEFAULT 0.00,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 创建索引加速查询
CREATE INDEX idx_user_budget_scenarios_user ON user_budget_scenarios(user_id);

-- 行级安全策略 (RLS)
ALTER TABLE user_budget_scenarios ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can manage their own budget scenarios"
  ON user_budget_scenarios
  FOR ALL
  USING (auth.uid() = user_id)
  WITH CHECK (auth.uid() = user_id);
```

### 5.3 Flutter 客户端集成与 CRUD 操作规范

```dart
import 'package:flutter/material.dart';
import 'package:supabase_flutter/supabase_flutter.dart';

class BudgetScenarioService {
  final _supabase = Supabase.instance.client;

  // 1. Create: 保存为新预案
  Future<void> createScenario({
    required String scenarioName,
    required String originPoskod,
    required String targetPoskod,
    required double housing,
    required double food,
    required double utility,
    required double transport,
    required List<Map<String, dynamic>> customExpenses,
    required double calculatedDiff,
  }) async {
    final user = _supabase.auth.currentUser;
    if (user == null) throw Exception("请先登录");

    await _supabase.from('user_budget_scenarios').insert({
      'user_id': user.id,
      'scenario_name': scenarioName,
      'origin_poskod': originPoskod,
      'target_poskod': targetPoskod,
      'housing_expense': housing,
      'food_expense': food,
      'utility_expense': utility,
      'transport_expense': transport,
      'custom_expenses': customExpenses,
      'calculated_diff': calculatedDiff,
    });
  }

  // 2. Read: 读取当前用户的所有预案列表
  Future<List<Map<String, dynamic>>> fetchUserScenarios() async {
    final user = _supabase.auth.currentUser;
    if (user == null) return [];

    final response = await _supabase
        .from('user_budget_scenarios')
        .select()
        .eq('user_id', user.id)
        .order('created_at', ascending: false);

    return List<Map<String, dynamic>>.from(response);
  }

  // 3. Update: 更新指定预案的开销参数
  Future<void> updateScenario({
    required String scenarioId,
    required double housing,
    required double food,
    required double utility,
    required double transport,
    required List<Map<String, dynamic>> customExpenses,
    required double calculatedDiff,
  }) async {
    await _supabase.from('user_budget_scenarios').update({
      'housing_expense': housing,
      'food_expense': food,
      'utility_expense': utility,
      'transport_expense': transport,
      'custom_expenses': customExpenses,
      'calculated_diff': calculatedDiff,
      'updated_at': DateTime.now().toIso8601String(),
    }).eq('scenario_id', scenarioId);
  }

  // 4. Delete: 删除废弃预案
  Future<void> deleteScenario(String scenarioId) async {
    await _supabase
        .from('user_budget_scenarios')
        .delete()
        .eq('scenario_id', scenarioId);
  }
}
```
