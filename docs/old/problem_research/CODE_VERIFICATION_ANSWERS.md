# LocateMY 当前代码验证答案

> 核对范围：当前工作区 `lib/`、`pubspec.yaml` 及路由/Provider 注册代码。结论以当前代码为准，不沿用旧说明文档或截图推断。

## A. 全局与导航

### Q01：认证门控与主页面

- **结论：** `AppShell` 直接以 `AuthViewModel.isAuthenticated`（本质是 Supabase `currentUser`/认证事件中的 session user）门控；无用户显示登录页，有用户显示主应用。全新进程中登录后默认是首页。
- **实际行为：** `NavigationViewModel` 初始索引为 0；首页和地图用 `IndexedStack` 承载，所以二者在 Tab 间切换时不会销毁，各自的滚动/地图及局部状态通常保留。若同一进程中曾停在地图后退出再登录，导航索引没有被重置，可能仍落在地图，而不是首页。
- **数据是否持久保留：** 页面状态只在当前进程/Provider 生命周期内保留；代码没有把导航索引写入本机存储。Supabase 会话由 SDK 管理，启动时读取 `currentUser`。

### Q02：地图中的分析入口

- **结论：** 六个入口都有实际页面/导航回调，但前置条件并不一致；只有“周边设施”在入口处强制要求主地图的 `selectedLocation` 已存在。
- **实际行为：** 生活成本、治安、社会经济走命名路由；基础设施、周边设施、公共交通走 `MaterialPageRoute`。生活成本无地点时用吉隆坡/新山默认名；治安和公共交通无选点时用吉隆坡坐标；社会经济和基础设施无选点时用 Petaling。周边设施若未在显示模式下选出 `selectedLocation`，只弹“请先在地图上选择一个地点”，不会打开。特别是对比模式的 origin/destination 不等于 `selectedLocation`：除生活成本会读取两端名称外，其余多个单地点分析页仍读取 `selectedLocation` 或默认地点。
- **数据是否持久保留：** 六页都读取全局 `LocationViewModel` 的当前内存状态；只有收藏地点另有 SQLite 持久化。

### Q03：语言切换

- **结论：** 中英文切换是全局 `MaterialApp.locale` 切换，但国际化只覆盖使用 `AppLocalizations` 的文案，并非全页面完整翻译。
- **实际行为：** AppShell、登录/注册、首页、地图及各分析页都有部分本地化；账户、房产、周边设施、隐患管理及分析页中仍散布固定中文或英文。例如账户退出确认固定英文，周边设施大部分固定中文，房产档案/详情/对比大量固定英文，生活成本“查看商家”附近和错误提示有固定中文，地图同步提示与周边设施标题固定中文。
- **数据是否持久保留：** `LocaleViewModel` 默认中文且只改内存字段，没有 SQLite/SharedPreferences/远端写入。完整重启会回到中文；同一进程内退出再登录不会销毁该 Provider，所以语言仍保留。

### Q04：首页刷新

- **结论：** 刷新会强制重新取得首页整组宏观统计；冷却时间为 1 分钟。
- **实际行为：** 仓库重新查询收入、通胀、全国基础设施、犯罪趋势、GDP、失业率并重算搬迁指数；OPR 仍是固定 3.00。AppBar 刷新时图标变转圈且按钮禁用，避免重复提交；成功强制刷新后开始 60 秒冷却。冷却期按钮仍可点，但只显示带剩余秒数的浮动 SnackBar，不发请求。首页还支持下拉刷新；冷却期下拉会由 ViewModel 拒绝，但该路径不会像 AppBar 按钮那样立即展示剩余秒数。
- **数据是否持久保留：** 结果写入本机 SQLite `cached_reports`，非强制加载最多复用 24 小时；冷却时间只在内存中。

## B. 登录、注册与账户身份

### Q05：登录表单规则

- **结论：** 邮箱必须非空且匹配代码正则；密码至少 8 个字符，登录页不检查大小写、数字或特殊字符。
- **实际行为：** 邮箱正则为 `^[\w-.]+@([\w-]+\.)+[\w-]{2,4}$`；密码提交时会 `trim()`。表单错误显示在输入框下；Supabase 错误通过 SnackBar 显示，少数已知错误会本地化，其他错误直接显示服务端原文。提交期间按钮禁用并显示进度圈，因此能防止重复提交。
- **数据是否持久保留：** 表单文本不持久；成功后的认证会话交给 Supabase SDK。

### Q06：注册表单规则

- **结论：** 四项均有校验；密码要求至少 8 位，并同时含小写、大写、数字、特殊字符且不能有空白。
- **实际行为：** 用户名必填，去掉普通空格后至少 3 字符，只允许英文字母、数字和普通空格；没有最大长度。邮箱规则与登录相同。确认密码必须与密码完全一致。加载期间按钮禁用并转圈。注册成功后代码一律显示成功 SnackBar 并 `Navigator.pop`；它没有显式判断 `AuthResponse.session` 或显示“请验证邮箱”。若 Supabase 项目允许立即建立 session，认证监听会使主应用出现；若启用邮箱确认且没有 session，则返回登录页等待用户自行完成验证。
- **数据是否持久保留：** 账号与用户名 metadata 交给 Supabase；表单草稿不保留。

### Q07：已验证用户标识

- **结论：** “Verified User”并不依据邮箱验证字段或任何条件，而是对所有已登录用户固定显示。
- **实际行为：** 账户页只读取用户邮箱；成功样式的 `StatusBadge(l10n.verifiedUser)` 无条件构建。未验证账户没有替代文案或不同状态。
- **数据是否持久保留：** 这是固定界面状态，不是保存的数据。

## C. 地图、选址与收藏

### Q08：地图右侧按钮

- **结论：** 从上到下共五个圆形按钮：刷新隐患、收藏列表、隐患图层、清除选址、分析报告；没有“定位到 GPS”或切换底图的按钮。
- **实际行为：** 刷新从 Supabase 重拉隐患并立即显示同步 SnackBar；收藏打开收藏对话框；警告图标切换隐患 MarkerLayer；`location_off` 清除 selected/origin/destination，无选择时禁用；分析图标打开/关闭右侧六入口面板。页面底部另有非圆形“上报隐患”FAB，会以当前显示模式选点或地图中心作为报告位置。
- **数据是否持久保留：** 图层开关和分析面板状态仅当前进程；清除只清全局选址，不删除收藏；刷新影响内存中的远端隐患列表。

### Q09：显示模式

- **结论：** 搜索结果、地图点击和收藏选择都会直接覆盖全局 `selectedLocation/selectedName`；没有要求先清除旧地点。
- **实际行为：** 搜索结果和收藏选择后还会把地图移动到该点并缩放到 15；普通地图点击只设置选点（地图本身已经位于点击视野）。若坐标与某收藏在约 11m 内，名称自动使用收藏名。显示模式与对比模式切换不会自动清掉另一模式已有的地点状态。
- **数据是否持久保留：** 当前选点只在 Provider 内存中，Tab 切换时因 `IndexedStack` 保留，完整重启丢失。

### Q10：对比模式

- **结论：** 用户需要通过点“Origin Address / New Address”对应选择框来确定当前要填哪一侧；之后可选收藏或选择“Pick on Map”，搜索和地图点击也会写入当前激活侧。
- **实际行为：** 两点没有去重检查，可以完全相同。每侧右边的 X 可单独清除，右侧全局清除按钮可同时清除两侧；可直接再次选择来替换。中间的双向箭头只是图标，没有交换回调，因此不支持一键交换。
- **数据是否持久保留：** origin/destination 仅内存保存，切 Tab/进入分析页仍在，完整重启丢失。

### Q11：地点搜索

- **结论：** 当前搜索是输入即请求的自动补全，不是按提交键后搜索。
- **实际行为：** `TypeAheadField` 每次查询调用 Geoapify autocomplete；选择结果后写入显示模式选点或对比模式当前侧，并移动地图。请求 URL 已带 `filter=countrycode:my`，客户端又以马来西亚矩形边界复核；若仍得到范围外坐标，显示“超出马来西亚范围”SnackBar并保持旧选点。仓库中的单结果 `search()` 当前没有被地图页使用。
- **数据是否持久保留：** 搜索结果本身不缓存/不持久；选中后只进入全局内存选址，除非用户另行收藏。

### Q12：收藏地点

- **结论：** 先在地图产生地点详情卡，再点卡片中的“保存地点”；收藏列表支持跳转和直接删除，不支持编辑，删除无确认。
- **实际行为：** 保存时要求名称非空，字段为本机毫秒时间戳 id、名称、经纬度、synced、createdAt。列表点条目会把它设为显示模式 `selectedLocation` 并移动地图；垃圾桶立即删除。收藏首先写本机 SQLite，然后登录状态下将未同步项 upsert 到 `user_saved_regions`。
- **数据是否持久保留：** 会跨应用重启和退出登录保留在设备 SQLite；本地表没有 user_id，因此同一设备换账号仍会看到同一批收藏。代码只“上传未同步项”，没有从远端下载收藏，所以换设备不会在应用中自动恢复。已登录删除会尝试同步删除当前账号的云端行。

### Q13：地图点选与长按

- **结论：** 普通点击负责选址；长按无论显示模式还是对比模式都会尝试打开隐患上报，不是特定模式限定。
- **实际行为：** 普通点击在显示模式替换 selected，在对比模式写入当前激活的 origin 或 destination。长按使用长按的精确坐标；若越出马来西亚矩形则只提示。底部上报按钮则优先用 `selectedLocation`，没有时用当前地图中心；它不会优先采用 origin/destination。
- **数据是否持久保留：** 地图点选仅内存；成功提交的隐患写远端。

## D. 隐患上报与隐患地图

### Q14：隐患类型

- **结论：** 完整类型为 `flood`、`crime`、`traffic`、`infrastructure`、`other`，确实有 Other。
- **实际行为：** 类型选择器遍历 enum，并直接显示 `type.name.toUpperCase()`；详情也同样显示 enum 名。类型名称没有使用本地化资源，因此中英文切换不会翻译它们。
- **数据是否持久保留：** 类型作为 enum 名写入远端 `hazard_type`。

### Q15：新建隐患校验

- **结论：** 只有标题被实际判定为必填；描述可空，类型不必由用户主动选择（默认 Other），三者都没有限长。
- **实际行为：** 标题只检查 `text.isNotEmpty`，纯空格也能通过。长按入口用长按点；FAB 用当前 `selectedLocation` 或地图中心。点击添加后立即发起异步创建并关闭 Bottom Sheet，没有等待结果或成功/失败提示；ViewModel 先乐观加入，远端保存失败会静默移除，成功后延迟刷新。
- **数据是否持久保留：** 保存成功写入 Supabase `crowdsourced_hazards`；失败不保留。

### Q16：隐患详情与投票

- **结论：** 主地图点击隐患标记后显示标题、类型、描述、赞成数、反对数，并提供赞成、反对、删除/取消样式按钮。
- **实际行为：** 投票只修改 `HazardViewModel` 内存计数，不调用 Repository；Bottom Sheet 本身拿的是旧 hazard 对象，点票后通常要关闭再打开才看到新数字。刷新/重启会重新以远端值覆盖，因此投票不会保留。详情底部红色按钮的文案使用 `l10n.cancel`，但实际执行的是仅内存删除，不删除 Supabase；远端刷新后会重新出现。
- **数据是否持久保留：** 隐患原记录是远端数据；此详情中的投票和删除都不持久。

### Q17：我的隐患报告

- **结论：** 支持查看列表、手动刷新、定位到主地图和删除；不支持编辑。
- **实际行为：** 页面加载当前 Supabase 用户的报告；点条目把报告位置设为全局选点、移动地图、切到地图 Tab 并退回根路由。删除前有永久删除确认；确认后从 Supabase 删除，并同步从共享 HazardViewModel 列表移除，因此主地图隐患图层也会消失。
- **数据是否持久保留：** 列表和删除均针对远端 `crowdsourced_hazards`；删除是永久的，没有回收站。

## E. 生活成本与预算预案

### Q18：预算输入

- **结论：** “当前月支出”输入框只在没有可用预算预案金额时出现，位于生活成本页顶部购买力卡中。
- **实际行为：** 输入后只即时更新该小组件下方的“等效预算”，计算为输入金额 × 目标 CPI / 原地 CPI；不会改写整页 `comparisonData`，也不会写入当前预案。若已有预案，界面直接显示预案的 `max_rent + living_expenses + transport_allowance` 及换算结果，不显示这个输入框。
- **数据是否持久保留：** 输入值只在 `_BudgetConverterState` 内存中，离开页面后丢失，退出/重新登录也不保留。

### Q19：预算预案字段

- **结论：** 远端实际读取/保存的是 id、用户 id、预案名、最高租金、生活开销、交通津贴和更新时间；模型另有 `entertainmentWeight`，但它没有对应远端读取/写入，也没有当前 UI 控件。
- **实际行为：** 新建、选择、重命名、删除都连接 `user_budget_scenarios`。新建/重命名没有空名称校验。UI 在只剩一个预案时隐藏删除按钮；删除当前选中项后改选列表第一项，没有按更新时间或邻近项选择。预案切换本身不会强制重新拉取同一地点对比，因此已展示的金额可能不立即按新预案重算。
- **数据是否持久保留：** CRUD 是按 Supabase 当前用户远端持久化；当前选中的预案 id 只在内存。

### Q20：查看商家

- **结论：** 仅有界面，当前无功能。
- **实际行为：** “View Stores / 查看商家”按钮的 `onPressed` 是空函数，不打开列表、地图或商家详情。
- **数据是否持久保留：** 无。

### Q21：商品与支出对比

- **结论：** 微观商品列表没有点击交互；“支出对比图”不是住房/食品/交通等预算类别，而是两地同名 PriceCatcher 商品均价的分组柱状图。
- **实际行为：** 列表最多展示目标地区前 8 个商品的名称和 RM 均价。图表以 `item_name` 做交集，展示原地价与目标地价，并按原地价格降序；任一端缺失该商品就不进入图表。没有共同商品时显示“两地暂无相同商品均价可对比”，不伪造空柱或替代类别。
- **数据是否持久保留：** 商品数据来自 Supabase RPC，整组对比会写入 3 天本地缓存；列表本身无用户修改。

## F. 治安、犯罪与房产入口

### Q22：犯罪类别按钮

- **结论：** 是真实可切换的 `FilterChip`，但只筛选犯罪趋势折线，不改变总体安全指数或安全地图。
- **实际行为：** “全部”固定存在，其余按钮由数据库最新分类 breakdown 动态生成，不一定只限 Violent Crime / Property Crime；仅 `assault` 和 `property` 被翻译为这两个名称，其他 key 原样显示。每个按钮的括号数字是最近一年该分类数量；切换后使用 `trend_by_category` 更换折线序列和年份范围。
- **数据是否持久保留：** 当前筛选只在该卡片 State 内存中；犯罪数据来自远端并有 3 天本地缓存。

### Q23：安全地图

- **结论：** 两个圆形图层按钮分别切换警区边界和 10km 内众包隐患。
- **实际行为：** 边界来自 `police_districts_boundary`，隐患来自全局隐患列表后按 10km 客户端过滤。隐患 Marker 可点，详情显示标题、类型、描述，但这里没有投票/删除。“查看主地图”只把主地图相机移动到本页分析的 latLng 并切换地图 Tab；不会把警区边界带回主地图，也不会另设一个新选点。无主地图选点时使用的默认吉隆坡坐标也只会移动相机，`selectedLocation` 仍可为空。
- **数据是否持久保留：** 图层开关仅页面内存；边界和隐患为远端数据。

### Q24：房产实勘入口

- **结论：** 顶部“Property Inspection Portfolio”标题进入完整房产档案；右下 Add Property 进入新增表单；顶部列表最多显示 3 项。
- **实际行为：** 每个房产整行（包括显示的评分/安全分区域）点击后进入房产详情；评分本身没有单独页面。超过 3 项只显示 `and N more properties...` 文本，该文本本身不可点，但上方标题可进入档案。
- **数据是否持久保留：** 这些条目来自 `PropertyViewModel` 内存列表，初始为 5 条演示数据。

## G. 房产新增、档案、对比与回收站

### Q25：房产表单完整字段

- **结论：** 可编辑字段为：房产名称、价格、收藏地点、四项季风评分、当地水灾迹象开关、照片占位项、备注。没有单独可输入的地址、综合评分或警区/安全分字段。
- **实际行为：** 名称必填但不限长；价格只检查非空，非数字最终会保存成 0；收藏地点在提交时必选。四项为排水、防水、湿度、照明，默认各 3/5；综合评分由四项算术平均自动生成。水灾历史默认 false；照片默认空、主图索引 0；备注默认空且非必填。编辑时以上值从现有对象带入。
- **数据是否持久保留：** 保存进房产 ViewModel 内存列表，未写 SQLite 或远端。

### Q26：地图选房产位置

- **结论：** “Pick on Map”不是带返回结果的选点路由；它直接关闭到根页面并切换地图 Tab。
- **实际行为：** 新增表单会把名称、价格、已选收藏 id、四项评分实时存到 `PropertyViewModel` 草稿；备注、水灾开关、照片不进草稿。用户需在地图完成选点/收藏后，再从治安页重新进入 Add Property。重新进入时只有当地图选点与某个已收藏地点约 11m 内匹配时才自动选择该收藏；普通未收藏点不会回填。没有专门“完成/取消选点”按钮。编辑模式没有草稿监听，点 Pick on Map 后原编辑页面被弹掉，未保存修改不会带回。
- **数据是否持久保留：** 草稿只在当前 Provider 内存，退出登录仍可能留在同进程，但应用重启丢失。

### Q27：房产照片

- **结论：** 不会调用相机或相册；“Add Inspection Photo”只是追加 `mock_photo_N` 字符串。
- **实际行为：** 支持追加多项（无代码上限）、删除、点缩略块设置主图。编辑页只画通用图片图标；保存后档案/详情用房产 id 和索引访问 Picsum 随机网络图，并不使用真实照片路径或上传文件。
- **数据是否持久保留：** 照片字符串只随内存房产对象存在，应用重启全部丢失；没有本机文件保存或 Supabase Storage 上传。

### Q28：房产风险资料

- **结论：** 表单中的风险“预览”是固定模拟值；真正保存时若有坐标，会调用 Supabase 自动取得警区、安全分和附近隐患数。
- **实际行为：** 预览仅按收藏名是否包含 `Sentul` 显示两套固定数据。ViewModel 层允许无坐标直接保存并留下 null 风险字段，但当前 UI 强制选择带坐标的收藏地点。真实风险查询若抛异常，`addInspection/updateInspection` 没有 try/finally，保存会中断且页面可能一直处于提交状态；不会降级保存。详情展示安全分、警区、水灾历史、四项评分（另有地址/价格/综合评分/照片/备注），不展示附近隐患数；对比页展示安全分、水灾历史、附近隐患数、综合评分及四项评分。
- **数据是否持久保留：** 查询源为远端，结果只拷贝进内存房产对象。

### Q29：房产持久化

- **结论：** 新增、编辑、软删除、恢复及回收站都只在运行内存；没有房产 Repository/SQLite/Supabase 写入。
- **实际行为：** 完整重启会丢失用户房产和回收站，并重新生成 5 条示例：Skyline Residence、Penang Heritage Stay、JB Waterfront Condo、Kinabalu Peak Apartment、Kuching River View。示例更新时间以每次启动时的 `DateTime.now().subtract(...)` 生成，因此是“启动时生成的演示数据”。同一进程退出登录或换账号不会重建/清空 PropertyViewModel，房产会跨账号共用。
- **数据是否持久保留：** 仅当前应用进程；不跨重启。

### Q30：房产档案

- **结论：** 没有搜索、排序或筛选。
- **实际行为：** 单条可点击进详情；详情可编辑或确认后软删除；档案中也可左滑、确认后软删除。顶部可进入回收站、进入多选对比模式。账户中心和治安页最终都 push 同一个 `PropertyArchiveScreen`，行为没有差异。
- **数据是否持久保留：** 所有操作只改共享的内存 PropertyViewModel。

### Q31：房产对比

- **结论：** 在档案页点 Compare 进入多选；最少 2 项，没有最大数量限制。
- **实际行为：** 对比页完整表格字段为价格、安全分、水灾历史、附近隐患数、综合评分、排水、防水、湿度、照明；顶部另显示每个房产名的占位卡，不呈现真实照片。页面没有保存按钮，也没有写入账户页 Saved Comparisons。
- **数据是否持久保留：** 选择和结果仅当前导航/内存，不保存。

### Q32：回收站

- **结论：** 支持逐条恢复和“Clear All”清空；不支持逐条永久删除。
- **实际行为：** 恢复立即执行且显示 SnackBar。清空有二次确认，确认后清空内存列表。没有删除时间字段、定时器或过期判断，因此不会自动过期。
- **数据是否持久保留：** 回收站只在内存，应用重启即消失（同时示例房产重新生成）。

## H. 社会经济

### Q33：用户收入位置

- **结论：** 输入家庭月收入后优先显示“高于该地区约 X% 家庭”的拟合百分位；不能把该用户明确标成 B40/M40/T20。
- **实际行为：** 百分位用当前地区拟合的对数正态分布计算。无法拟合但有中位数时，只显示高于/低于该地区中位数。页面上 B40/M40/T20 是地区家庭结构占比和官方门槛背景，不是对输入用户的阶层归类。
- **数据是否持久保留：** 输入只在页面 State，离开并销毁页面、重启或重新登录均丢失。

### Q34：两地对比含义

- **结论：** 社会经济页并没有同时对比两地；它只分析 `selectedLocation/selectedName`，无选点时分析 Petaling。
- **实际行为：** 在对比模式中，顶部共用选择器会显示并允许修改 origin/destination，但社会经济页生成请求 key、坐标和标题时完全不读取这两个字段，因此切换两端通常不会改变分析结果。页面内也没有“分析原地址/新地址”的专用切换状态。
- **数据是否持久保留：** 单地点结果来自远端并有 3 天 SQLite 缓存；顶部两端选择仅全局内存。

## I. 基础设施

### Q35：个性化需求权重

- **结论：** 可见滑块只有医疗重要性、教育优先级、商业便利性；第三项实际控制 `transit` 权重。
- **实际行为：** 滑动时滑块自身的浮动 label 在 1–10 间变化，并即时重算下方 ICI 数值；每行右侧显示的是原始设施得分，不是权重，所以不会随滑块变化。供水和供电各有默认 0.2 权重且计算时使用，但没有可见滑块。五项默认都为 0.2。
- **数据是否持久保留：** 权重只存在 InfrastructureViewModel 内存，切页面/退出登录但进程仍在时保留，完整重启丢失。

### Q36：数据不完整提示

- **结论：** 缺项时仍会计算综合分：适用但缺源数据的项按 0 分计入，并在卡片显示“数据不完整”及缺失项文字。
- **实际行为：** 单项卡显示 `—`；主卡显示计算后的分数（完全没有可评分项才为 `—`），并列出“缺少 X…缺失项按 0 计入指数，仅供参考”。若只是未提供坐标导致 transit 不可评估，交通项从分子分母都剔除且不算“缺失”。“数据不完整”是普通 `StatusBadge`，没有点击说明页或弹窗。
- **数据是否持久保留：** 数据来自远端并写 3 天本地缓存；完整性 UI 非用户数据。

## J. 周边设施

### Q37：设施分类与展示数量

- **结论：** 七类为医疗、教育、日常生活、交通、安全与服务、休闲与绿地、灾害与环境风险；每类只列最近 3 项，“以及其他 N 个地点”不能展开。
- **实际行为：** 实际查询/归类子类型包括：医疗 `hospital/clinic/doctors/dentist/pharmacy(amenity)`；教育 `school/university/college/kindergarten/childcare`；生活 `bank/atm/marketplace/food_court/restaurant/fast_food/cafe/fuel/library/community_centre/cinema/theatre/townhall` 及 shop 的 `supermarket/convenience/mall/pharmacy`；交通 `bus_station/ferry_terminal/charging_station`、railway 的 `station/halt/tram_stop`、`bus_stop`、`toll_booth`；安全 `police/fire_station/post_office`；休闲 `place_of_worship/park/garden/sports_centre/fitness_centre`；风险 `industrial`。分类器还识别 `motorway_junction` 为交通，但当前 Overpass 查询只抓 `highway=bus_stop`，所以正常查询不会返回它。未命中专门规则的已查询 amenity 会回退到生活类；`toll_booth` 和 `industrial` 因类型提取器未读取 barrier/landuse，条目类型文案还可能退成 `Facility`。
- **数据是否持久保留：** 设施从 OSM Overpass 实时拉取，仅保留在 ViewModel 内存，同坐标在当前进程复用；无 SQLite 持久缓存。

### Q38：设施条目交互

- **数据是否持久保留：** 无用户交互数据。

### Q39：地点选择器

- **结论：** 顶部选择器只列本机收藏地点，不提供搜索、当前位置或任意地图点列表。
- **实际行为：** 显示模式下选择收藏会立即改 `selectedLocation`，页面监听坐标变化并重新查询。对比模式下它显示 origin/destination 并写入相应侧，但周边设施页实际仍只读取 `selectedLocation`，因此切换两端不会触发设施重查；而且从地图分析面板进入此页本身要求 `selectedLocation` 已存在。

## N. 截图与代码差异汇总

### Q49：无操作的可见控件

- **结论：** 明确空回调或装饰性伪入口如下。
- **实际行为：**（1）生活成本 “View Stores / 查看商家”按钮：空回调；（2）账户“Relocation Assessment History”：空回调；（3）账户两条 Saved Comparisons：空回调；（4）周边设施每项右箭头：纯 Icon，整行无手势；（5）分析页 origin/destination 中间的交换箭头：纯 Icon，不交换；（6）账户 My Comments / Liked Areas 卡片：无点击包装；（7）治安页 `and N more properties...`：只是文本，需点上方 Portfolio 标题才进入档案。另有“可见变化但业务未接通”的 Default Location 开关：能切换开关外观，却不影响任何其他页面。其余已扫描到的按钮至少有页面跳转、状态切换、弹窗、刷新或 SnackBar 等用户可见结果。
- **数据是否持久保留：** 上述空入口不产生数据；Default Location 仅页面内存。

### Q50：固定示例与真实功能

- **结论：** 当前应用是“真实远端公共数据 + 部分真实远端用户数据 + SQLite 缓存/收藏 + 大量内存原型状态”的混合体，并非所有截图区域都接了后端。
- **实际行为：** 数据来源汇总如下：
  - **固定常量：** 账户 Verified User、两条 Saved Comparisons、评论 3/点赞 12；首页 OPR=3.00（以及 ICI 缺失时计算搬迁指数用 85）；房产新增页保存前风险预览两套值；无选点时各分析页的 KL/JB/Petaling 默认地；社会经济官方门槛查询失败时的兜底常量。
  - **启动时生成的演示数据：** `PropertyViewModel` 的 5 条示例房产；名称/价格/风险等字段写死，更新时间按本次启动时间倒推。
  - **内存用户数据：** 新增/编辑/软删除/恢复房产与回收站、房产草稿和 mock 照片；地图当前选点/两地对比/图层开关；隐患投票和主地图详情中的临时删除；收入输入、临时月支出输入、当前预案选择；基础设施权重；Default Location 开关；语言和导航索引。
  - **本机持久数据：** SQLite `saved_locations`；`cached_reports` 中的首页、生活成本、治安、社会经济、基础设施等远端分析缓存。收藏不按账号隔离。
  - **远端用户数据：** Supabase Auth 与 `profiles`；`user_budget_scenarios`；`crowdsourced_hazards` 的新建/我的报告/永久删除；`user_saved_regions` 仅接收藏上传/删除，没有下载恢复链路。房产、照片、投票、默认地点、保存的对比、评论、点赞和语言均没有远端用户持久化。
  - **远端公共数据：** 首页宏观指标、CPI/PriceCatcher 商品、犯罪与警区边界、社会经济、基础设施、交通站点来自 Supabase；地点搜索来自 Geoapify；周边设施来自 OSM Overpass。
- **数据是否持久保留：** 是否保留取决于上列层级；尤其要注意“远端公共数据被本机缓存”不等于用户数据，以及“收藏上传远端”不等于能在新设备恢复。
