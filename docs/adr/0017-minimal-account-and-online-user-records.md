# 最小账号与在线业务记录

> Status: Accepted（整体范围与验收方式已确认；Issue #31 实现重构与验收进行中）— 2026-09-17

LocateMY 是一次性的大学项目，交付重点是 Flutter UI、键值存储、SQLite、设备文件与 Supabase 的使用。项目负责人确认保留邮箱密码注册、登录、退出、SDK 默认保持登录及当前用户身份；取消邮箱确认要求及其界面、自建会话管理、独立 Account Privacy 模块和跨 Feature 私有数据清理协议。Supabase SDK 的基础认证及简单记录归属权限保留，不用自建安全协调层包装它们。

账号业务记录只在线读写 Supabase；取消收藏离线创建、账号数据自动同步和照片待上传队列。公共缓存和课程展示所需的本地存储另行明确用途，不再为已删除的安全协议保存屏障文件。退出仅执行基础账号退出和普通页面生命周期处理，不以逐模块删除本机数据或提交清理证明作为完成条件。

本次允许重新审查全部 Feature/shared module，包括已开发代码和已批准设计；这不是对全部业务能力删除的批准。历史系统基线、提交承诺与 Development Contract 中和上述决定冲突的部分，以本次用户确认优先。此决定调整 ADR 0015、0016 所述契约和数据边界的适用范围，不代表实现已完成，也不修改原始大学提交稿。

项目负责人随后确认：继续要求登录后进入应用；采用普通 Flutter 路由、页面传参和具名业务服务，取消通用导航意图、组合槽位与贡献发布框架，保留必要职责和共享对象。取消跨重启房产草稿与个人化地点适配度总分；地图、六类分析、A/B 比较、收藏、预算、隐患和房产基本能力保留。房产回收站与恢复明确保留，不能按本轮精简删除；风险数据保存于实勘档案，仅在新增或坐标变化时重新计算，不在查看详情时重算，也不提供手动刷新。

Datafile 展示采用预算预案导出本机 JSON，并在应用中读取展示；它是导出副本，不自动同步或替代 Supabase 权威记录，退出不删除。SQLite 用于公共分析缓存，KV 保存语言与简单设置。账户五项评估偏好及其设置、保存逻辑和数据依赖一并删除；基础设施医疗、教育、交通三个 ICI 权重和当前预算预案保留。

新增或坐标变化时风险输入缺失仍允许保存实勘，并明确标记快照不可用；不以假数据或零补齐，不以旧坐标快照冒充新坐标风险，不增加自动补算。最终验收以应用页面入口的外部行为为主要 seam，复用 Widget 测试基础，辅以少量真实 Supabase 和本机存储检查；删除仅用于已取消安全协调协议的测试。用户已确认整体范围，后续执行由 [GitHub Issue #31](https://github.com/chewjs-wm25/LocateMY/issues/31) 追踪，标记为 `ready-for-agent`。
